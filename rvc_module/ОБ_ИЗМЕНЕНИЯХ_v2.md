# RVC v2 — что изменено под требования

Сопоставление каждого требования с тем, что реализовано.

## Требования смежного разработчика

| Требование | Реализовано |
|---|---|
| Оставить **численную** оценку реализуемости (для сравнения со своей) | `scoring.py`: балл 0..100 на каждую атаку и каждую позицию. В JSON — `findings[].assessments.<позиция>.numeric`. |
| Численная оценка **со всеми параметрами**: за что повысил/понизил и на сколько | `numeric.factors[]` — список факторов `{key, label, delta(+/-), evidence}`; `numeric.gates[]` — жёсткие отсечки. |
| **Сколько процентов** нужно для реализуемо / возможно / не реализуемо | `numeric.thresholds` у каждой оценки и `meta.scoring_model.thresholds`: `>=65` реализуемо, `35..64` возможно, `<35`/гейт — не реализуемо. |
| **Качественная** оценка с **обоснованием** | `assessments.<позиция>.qualitative` = `{label, color, justification}`. |
| Разделение **внутренний / внешний** атакующий, для обоих — численная и качественная | Три позиции: `external`, `internal_user`, `internal_admin`. Каждая несёт и `numeric`, и `qualitative`. |
| **Методичка реализации** атаки (подробно, по шагам — не «ПО + одна команда») | `findings[].methodic`: фазы (разведка/эксплуатация/пост-эксплуатация), в каждом шаге — действие, команда, ожидаемый результат, пояснение; плюс инструменты, траблшутинг, зачистка. |
| **Методичка защиты** от этих же атак | `findings[].defense`: обнаружение, харднинг, патч, проверка. |
| Всё это в **JSON**, который создаётся после обработки данных сканеров | `report.json` (схема 2). Генерируется `python -m rvc.pipeline --base tools`. |

## Требования преподавателя

| Требование | Реализовано |
|---|---|
| Качественная оценка словами: **реализуемо / возможно / не реализуемо** | `qualitative.label` ∈ {реализуемо, возможно, не реализуемо}. |
| Цвета **зелёный / жёлтый / красный** | `qualitative.color` ∈ {green, yellow, red}; на дашборде — цветные бейджи. |
| Разделить на атаки **изнутри** и **снаружи** | Колонки/вкладки по позициям; счётчики по каждой; в JSON — три позиции. |
| Более подробное описание, **чтобы студенты реально проводили атаки** | Полные методички с реальными командами и пояснениями (16 семейств). |

## Как это выглядит на дашборде

1. Кнопка в программе-сканере открывает наше окно → играет intro-анимация
   «нападение на узел» (без изменений, как было).
2. После неё — окно оценки: слева список атак со словами и цветами по трём
   позициям; клик по атаке → справа полная карточка.
3. По умолчанию видны **слова** (реализуемо/возможно/не реализуемо). Числовая
   параметрическая разбивка открывается по наведению на бейдж и по кнопке
   «численная разбивка» — она для смежной программы.

## Важно про данные этого стенда

В `tools/` нет инвентаризации хоста и Trivy, поэтому версии ПО и средства защиты
неизвестны. Из-за этого CVE-атаки (EternalBlue, BlueKeep, Zerologon и т.п.)
получают «возможно» (жёлтый), а не «реализуемо»: без подтверждения версии/патча
их нельзя признать полностью реализуемыми. Атаки, не зависящие от версии
(RPC/SMB-перечисление, relay изнутри, и т.д.), оцениваются по достижимости и
правам роли. Если сканеры начнут отдавать инвентаризацию хоста — модель
автоматически даст более точную (в т.ч. «зелёную») оценку по версии.

## Работа на ЛЮБОЙ машине (разные данные сканеров)

Софт общий, у каждого свои сервисы/CVE. Поэтому описание строится слоисто и
методичка есть всегда:

- **product** — точная методичка, если узнали конкретный продукт (по CVE/имени).
- **type** — корректная обобщённая методичка по классу атаки (RCE/brute/relay/…),
  если конкретики нет. Чужим продуктом НЕ подменяем (раньше Apache RCE показывал
  методичку EternalBlue — исправлено).
- **generic** — общий порядок исследования, если тип атаки не указан вовсе.

Основа видна и в JSON (`methodic_basis`), и на дашборде (пометка у методички).
Оценка (цвет/слово/числа) объективна для любых данных, т.к. вычисляется, а профиль
выполнения тоже слоистый (чужой `relay_attack` -> нужна L2-позиция -> снаружи
красный, изнутри зелёный — без отдельного семейства).

Чтобы добавить точную методичку под свой сервис — дополнить `families` (и CVE в
`mitre_kb.json`); чтобы расширить обобщённый слой — `TYPE_METHODICS`. Всё через
`build_methodics_kb.py`.

## Как пересобрать артефакты

    python -m rvc.build_methodics_kb           # methodics_kb.json
    python -m rvc.pipeline --base tools --out report.json
    python app.py                              # дашборд на :5000
